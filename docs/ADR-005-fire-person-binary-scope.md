# ADR-005：收缩为 Fire/Person 二分类口径的主线重训计划

**状态：** 进行中。已决定从三分类主线切换为 fire/person 二分类主线，并按新口径重训关键节点。  
**创建日期：** 2026-06-24  
**最后更新：** 2026-06-25  
**相关文档：** [ADR-003](ADR-003-fair-batch16-lr001-experiment-plan.md), [ADR-004](ADR-004-smoke-recall-improvement.md)

## 一、这份文档要解决什么问题？

到 ADR-004 为止，我们已经比较清楚地看到：

1. `B2` 相对 `A1` 在 **fire/person** 上持续获益；
2. `smoke` 与 `fire/person` 之间存在明显的类别竞争或特征冲突；
3. 想在保留 `B2` fire/person 收益的同时补回 smoke，目前代价高、问题复杂、短期内难以形成一条干净主线。

因此，本项目决定暂时收缩论文口径：

> 主论文不再把任务定义为 smoke/fire/person 三分类检测，而改为更聚焦、更容易讲清楚的 **fire/person 二分类检测**。

这不是否定 ADR-004 的工作价值。相反，ADR-004 提供了一个重要发现：

> 在当前双流多模态结构下，smoke 与 fire/person 很可能共享了部分有限表征能力；当高层跨模态交互加强 fire/person 判别时，smoke 更容易成为被牺牲的类别。

这个问题值得单独展开，但更适合作为后续研究，而不是当前论文的主线任务。

---

## 二、为什么要改成二分类重训？

如果论文正式宣称研究任务是 **fire/person 二分类检测**，那么严格来说，训练和评测都应该与该任务定义保持一致。

原因很简单：

1. 三分类和二分类不是同一个学习问题；
2. smoke 在三分类训练中会参与分类梯度，影响共享 backbone、neck 和 head；
3. 如果继续沿用三分类模型、只汇报 fire/person，两类指标虽然可参考，但任务口径并不完全一致。

因此，本 ADR 的核心决策是：

> 论文主结果、主对比和主创新链，统一切换到 **fire/person 二分类训练 + 二分类评测** 口径。

---

## 三、现在保留哪条主创新链？

为了尽量减少重训成本，同时保留一条完整、易于说明的结构演进路径，本轮只保留以下 5 个节点：

```text
F0 -> F2 -> D2.1 -> A1 -> B2
```

对应含义如下：

| 节点 | 结构变化 | 保留原因 |
| --- | --- | --- |
| F0 | 原始双流基线：无 P2 neck/head，P3 aux 关闭，P4 使用 A2C2f | 作为最简单、最可解释的起点 |
| F2 | 在 F0 基础上补齐 plain P2 neck/head + RGB/IR P3 aux | 作为稳定的四尺度增强基线 |
| D2.1 | 将 P2 plain fusion 替换为 DMGInit8d@P2 | 引入低层差分放大、共模抑制机制 |
| A1 | 在 D2.1 基础上加入 FreAtt@P3 | 引入中层频域跨模态交互 |
| B2 | 在 A1 基础上将 P4 A2C2f 替换为 Parallel Cross A2C2f | 引入高层跨模态语义交互，作为最终模型 |

## 四、哪些实验需要重训？

### 4.1 必须重训

以下模型必须按二分类口径重新训练：

1. `F0`
2. `F2`
3. `D2.1`
4. `A1`
5. `B2`

原因不是因为旧结果失效，而是因为：

- 新论文的任务定义已经改变；
- 主结果表中的所有模型都必须处于同一标签空间、同一损失定义、同一训练口径下；
- 只有这样，主链中每一步结构增益才能被严格解释为“对 fire/person 二分类任务的贡献”。

### 4.2 一并重做但不新增模型

除训练外，还需要同步重做：

- 二分类数据配置：`nc=2`，类别改为 `fire/person`；
- 所有主链模型 YAML 中的检测头类别数；
- 二分类下的正式验证表、逐类指标、曲线图；
- 参数量、FLOPs、速度统计；
- 论文中的主结果表和主消融表。

### 4.3 当前不再投入的实验

以下内容暂时不再作为主论文必要实验：

- `C1` 及整个 `C` 系列；
- ADR-004 中围绕 smoke 修复开展的 P01-P05 pilot；
- A1/B2 smoke 逐样本诊断、gradient probe 和其他 smoke 专项分析；
- 仅服务于三分类 smoke 问题的支线消融。

这些工作不会删除，但会从“当前论文主线”中移出。

## 五、对 ADR-003 和 ADR-004 的关系怎么理解？

### 5.1 ADR-003 现在扮演什么角色？

ADR-003 记录的是 **三分类阶段** 的完整主创新链证据。

它仍然有价值，因为它告诉我们：

- `F0 -> B2` 在 fire/person 上是持续增益的；
- `A1` 与 `B2` 的差别主要体现在高层跨模态交互如何重新分配类别收益；
- smoke 的加入会改变多类联合优化的平衡。

但从 ADR-005 开始，ADR-003 不再直接作为论文主结果，而是作为：

> 二分类收缩决策的前情背景和历史证据。

### 5.2 ADR-004 为什么归档？

ADR-004 不是失败，而是阶段性收束。

它已经完成了一项很重要的工作：

> 证明 smoke 问题不是一个简单调参问题，而是一个与类别竞争、跨层表示分配和高层跨模态交互相关的更深层问题。

这类问题值得单独研究，但当前并不适合作为主论文继续扩展。为避免主线发散，ADR-004 从今天起转为：

> 已归档的后续研究入口。

## 六、新主线要回答的核心问题

收缩到 fire/person 二分类后，论文需要回答的问题会更清楚：

1. 从基础双流检测器出发，哪些结构改动对 fire/person 最有效？
2. 低层差分融合 `DMGInit8d@P2` 是否能稳定提升目标检出与定位？
3. 中层频域交互 `FreAtt@P3` 是否提供额外收益？
4. 高层语义交互 `Parallel Cross@P4` 是否继续带来最终提升？

这条主线比三分类版本更聚焦，因为它不再需要同时回答：

- 为什么 smoke 被压制；
- 如何补回 smoke；
- 如何平衡三类目标之间的竞争关系。

## 七、执行计划

### 7.1 数据与配置

- 基于现有数据集生成 fire/person 二分类配置；
- 保持 train/val 划分不变，只调整标签空间；
- 所有主链模型使用统一 batch、lr、seed 和训练轮数；
- 继续沿用 ADR-003 的公平训练原则，除非另有明确记录。

### 7.1.1 数据增强口径

本轮二分类主线不默认沿用 YOLO 的强场景增强，尤其不优先使用 `mosaic`、`mixup` 和其他会改变整图空间组织关系的拼贴类增强。

原因很简单：

1. 本任务不是通用自然图像检测，而是 **双模态 fire/person 检测**；
2. fire、person 与背景之间存在相对稳定的场景关系；
3. RGB 与 IR 两种模态对同一场景存在物理对应关系；
4. 强拼贴增强虽然能增加样本多样性，但也可能破坏这种真实场景一致性和跨模态对应关系。

因此，ADR-005 默认采用更保守的训练口径：

> 优先保留真实场景结构，避免用会明显改写场景拓扑和模态对应关系的增强去换取表面多样性。

这并不意味着目标检测绝对不能做增强，而是当前论文主线更强调 **结构机制比较的可解释性**。如需引入增强，应优先考虑不会破坏物理一致性的轻量策略，并在独立对照中验证其必要性。

### 7.2 重训优先级

建议按以下顺序进行：

1. `F0`：建立新的二分类基线；
2. `F2`：确认四尺度 + P3 aux 在二分类下仍是稳定基础；
3. `D2.1`：验证低层差分融合对 fire/person 的独立贡献；
4. `A1`：验证 FreAtt@P3 的中层收益；
5. `B2`：验证高层 Parallel Cross 是否作为最终模型成立。

这样做的好处是：

- 任意节点训练完成后，都可以立刻更新主链；
- 如果中途发现某一步在二分类下不成立，可以尽早修正论文叙事；
- 不必等所有模型跑完才开始写结果部分。

### 7.3 记录规则

从现在开始，凡是进入论文主表的结果，都必须明确标注：

- 二分类数据配置路径；
- 训练命令；
- checkpoint 路径；
- 验证命令；
- 采用的是 best 还是 last；
- 对应的参数量和速度统计。

### 7.4 F0 二分类首个正式结果

`F0` 已完成首轮二分类训练，并以独立验证结果作为当前基线记录。

#### 训练与验证信息

- 训练目录：`runs/detect/train_fp_F0_dual_seed0_cls01/`
- 训练数据：`ultralytics/cfg/datasets/RGBT-3M-dual-fire-person.yaml`
- 验证数据：`ultralytics/cfg/datasets/RGBT-3M-dual-fire-person-local.yaml`
- 采用 checkpoint：`weights/epoch87.pt`
- 说明：`results.csv` 中 overall mAP50-95 峰值出现在 `epoch 88`，对应保存文件为 `epoch87.pt`

#### F0 二分类独立验证结果（epoch87.pt）

| 类别 | P | R | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: |
| all | 0.89895 | 0.88538 | 0.92334 | 0.55613 |
| fire | 0.90910 | 0.89297 | 0.92565 | 0.55936 |
| person | 0.88879 | 0.87779 | 0.92103 | 0.55289 |

#### 当前判断

这个结果说明两点：

1. `F0` 在二分类口径下已经形成一个稳定、可复验的基线；
2. 对于一个不含 `P2`、不含 `aux`、不含额外跨模态增强模块的双流基础模型而言，当前指标处于“可用且正常”的范围，但仍有足够空间供 `F2 -> D2.1 -> A1 -> B2` 继续提升。

`F2` 已完成首轮二分类训练，并以 `last.pt` 做一次独立验证。

#### 训练与验证信息

- 训练目录：`runs/detect/train_fp_F2_dual_seed0_cls01/`
- 训练数据：`ultralytics/cfg/datasets/RGBT-3M-dual-fire-person.yaml`
- 验证数据：`ultralytics/cfg/datasets/RGBT-3M-dual-fire-person-local.yaml`
- 采用 checkpoint：`weights/last.pt`
- 独立验证输出：`runs/detect/val/train_fp_F2_dual_seed0_cls01_last_once/`

#### F2 二分类独立验证结果（last.pt）

| 类别 | P | R | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: |
| all | 0.91261 | 0.88596 | 0.92335 | 0.55958 |
| fire | 0.91773 | 0.88621 | 0.92974 | 0.56939 |
| person | 0.90750 | 0.88570 | 0.91697 | 0.54978 |

#### 相对 F0 的初步变化

相对 `F0` 的独立验证结果（`epoch87.pt`）：

- overall mAP50-95：`0.55613 -> 0.55958`，提升 `+0.00345`
- fire mAP50-95：`0.55936 -> 0.56939`，提升 `+0.01003`
- person mAP50-95：`0.55289 -> 0.54978`，下降 `-0.00311`

这说明 `F2` 在二分类口径下仍能延续“三分类阶段对 fire 更友好”的方向，但当前 `last.pt` 对 person 的收益还不稳定。后续应进一步检查 `F2` 的 best epoch、曲线峰值和相对 `F0` 的阶段性变化，而不能仅凭最终 `last.pt` 下结论。

## 八、当前结论

本 ADR 做出的正式决策如下：

1. **主论文任务口径切换为 fire/person 二分类检测。**
2. **主创新链收缩为 `F0 -> F2 -> D2.1 -> A1 -> B2`。**
3. **上述 5 个节点全部按二分类口径重训。**
4. **ADR-004 归档为 smoke 三分类问题的后续研究入口，不再继续占用当前主线实验资源。**

一句话概括：

> 先把 fire/person 这条故事讲清楚、讲扎实；smoke 留到下一阶段，作为更有针对性的独立研究问题来处理。
