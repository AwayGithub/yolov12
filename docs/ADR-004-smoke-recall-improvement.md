## 一、这份文档要解决什么问题？

## 归档说明

从 `ADR-005` 开始，主论文口径已收缩为 **fire/person 二分类检测**。因此，ADR-004 中围绕 smoke 漏检开展的 pilot、C 系列设计和三分类补救思路，统一转为后续研究储备，不再继续占用当前主线实验资源。

这不代表 ADR-004 无效。相反，它已经提供了一个关键判断：

> smoke 与 fire/person 之间存在更深层的特征冲突或类别竞争问题，短期内不适合继续作为当前主论文的主线优化对象。

下面的内容保留原始记录，供后续单独研究 smoke 三分类问题时继续使用。

ADR-003 已经确定论文的主创新链：

```text
F0 -> F1 -> F2 -> D2.1 -> A1 -> B2
```

B2 在 fire 和 person 上取得了收益，但 smoke Recall 比 A1 下降了 `0.02223`。Recall 表示真实目标中有多少被模型找出来，下降意味着漏检增加。

ADR-004 的目标是：

> 在不破坏 B2 对 fire/person 收益的前提下，弄清楚烟雾为什么更容易漏检，并寻找有物理解释、可以经过实验验证的改进方法。

本阶段不直接猜一个模块然后训练，而是先进行 Pilot Study。

**Pilot Study** 指成本较低的先导实验。它的作用是验证一个想法有没有数据依据，再决定是否进入 200 epoch 的正式训练。

**C 系列** 指 ADR-004 后续开展或计划开展的正式模型实验。`C1` 已完成训练并得出负结论，B2 仍作为 C0 对照。

本文中的 **RGB** 指普通可见光彩色图像，**IR** 指红外图像。

## 二、目前最重要的结论

截至 C1，已经得到以下结论：

1. **烟雾确实具有可解释的图像特征。** 它通常边缘较弱、纹理较少、结构弥散。
2. **烟雾与火焰的主要差异在红外图像。** 火焰具有更强的热边界和目标/背景对比。
3. **烟雾与人员的主要差异在 RGB 图像。** 人员的轮廓和纹理更清楚。
4. **但这些原图特征不能解释 B2 为什么额外漏掉某些烟雾。** P02 中 8 个核心指标的 AUC 都接近随机水平。
5. **B2 的新增漏检与网络内部 P3/P4 和检测头响应下降有关。** 这是目前更直接的机制证据。
6. **暂时关闭 P4 变换强度能恢复部分内部响应，但这些变化不能转化为完整验证集上的稳定最终检测改善。** P03 中 8 种 P4 方向性干预均未超过原始 B2，部分干预可提高 smoke Recall，但伴随 mAP50-95 下降。
7. **P4 方向性强度调整不是修复 B2 smoke Recall 的可靠 shortcut。** IR 方向残差对维持 smoke Recall 更重要，RGB 方向残差会轻微压制部分 smoke 响应，但都不足以单独修复问题。
8. **物理信息在冻结 B2 ROI 特征之外仍有增量。** P04/P04b 中 Combined 对 smoke-vs-hard-background 的 AUC 从 0.61788 提高到 0.85879，对 smoke-vs-fire 从 0.55462 提高到 0.89260，且随机/置乱对照没有复现该提升。
9. **物理信息更适合注入低层/中层（P2/P3），而不是高层（P4/P5）。** P05 中 smoke-vs-background 最佳在 P2，smoke-vs-fire 最佳在 P3，smoke-vs-person 也在 P2/P3 更有效。
10. **但 C1 没有把这些 Pilot 证据转化为最终 smoke 改善。** `PhysicalGuidance@P2/P3` 在完整 200 epoch 训练后，smoke Recall 没有高于 B2，fire/person mAP50-95 也未保住。
11. **这进一步支持 ADR-005 的收缩决策。** smoke 问题不像一个轻量物理先验注入模块就能修复，更像类别竞争、表示分配和高层语义交互共同作用的结果。

因此，本阶段的最终决策是：

> P04/P05 的证据足以支持“物理信息在冻结分析中有增量”这一判断，但首个正式方案 `C1` 未能把该增量转化为最终 smoke 修复。因此，ADR-004 以 `C1` 负结果收束：当前不再继续投入 smoke 主线训练，相关问题转入后续独立研究。

## 三、主创新链背景

| 节点 | 相对前一节点的变化 | 作用 |
| --- | --- | --- |
| F0 | 无 P2 neck/head，关闭 P3 辅助监督，P4 使用 A2C2f | 双流检测基础结构 |
| F1 | 加入普通 P2 neck/head | 扩展为 P2-P5 四尺度检测，主要改善小目标 fire/person |
| F2 | 加入 RGB/IR 单模态 P3 辅助检测头 | 恢复 smoke Recall，并约束新增低层路径 |
| D2.1 | P2 普通融合替换为 DMGInit8d | 在低层利用两种模态的差异和共同信息 |
| A1 | 加入 FreAtt@P3 | 在中层加入频域跨模态交互，是主链中最明确的整体收益节点 |
| B2 | P4 A2C2f 替换为 Parallel Cross A2C2f | 在高层加入跨模态语义交互，提升 fire/person，但损失 smoke |

这里的 P2、P3、P4、P5 是网络中不同分辨率的特征层。数字越小，通常保留的空间细节越多；数字越大，通常语义更强、分辨率更低。

**neck** 是融合不同尺度特征的网络部分；**head（检测头）**负责最终输出类别、位置和置信度。A2C2f、DMGInit8d、FreAtt 和 Parallel Cross 是本项目中不同特征处理或融合模块的名称，表格第三列已经说明各自作用。

主论文可以将这条链概括为：

> 面向火灾场景中的烟、火、人三类目标，在不同特征层使用具有针对性的多模态融合方法。

ADR-004 不改变这条主链，而是在 B2 基础上专门研究 smoke 漏检。

## 四、A1 与 B2 到底差在哪里？

### 4.1 正式验证指标

| 实验 | 类别 | Precision | Recall | mAP50 | mAP50-95 |
| --- | --- | ---: | ---: | ---: | ---: |
| A1 | smoke | 0.94311 | 0.90357 | 0.95118 | 0.74394 |
| B2 | smoke | 0.94738 | 0.88134 | 0.94264 | 0.73570 |
| B2 - A1 | smoke | +0.00427 | **-0.02223** | **-0.00854** | **-0.00824** |

指标解释：

- **Precision（精确率）**：模型报出的烟雾中，有多少确实是烟雾；
- **Recall（召回率）**：真实烟雾中，有多少被模型找出来；
- **mAP50**：预测框与真实框重叠达到 0.5 时的综合检测表现；
- **mAP50-95**：在多个更严格重叠标准下取平均，更全面地反映分类和定位质量。

B2 的 Precision 略高，但 Recall 明显下降，说明它对 smoke 更保守：误报没有增加，但漏检更多。

与此同时，B2 相对 A1 的 fire/person mAP50-95 分别提高 `+0.00503/+0.00195`。因此 B2 不是整体退化，而是不同类别之间的收益发生了重新分配。

### 4.2 逐目标诊断

| 观察项 | 结果 | 通俗解释 |
| --- | ---: | --- |
| 验证集 smoke 真实目标数 | 4086 | 分析总体 |
| A1 检出、B2 漏检 | 182 | B2 新增漏检 |
| A1 漏检、B2 检出 | 84 | B2 新增检出 |
| B2 净减少检出 | 98 | 182 - 84 |
| 182 个新增漏检中的低置信度漏检 | 111 | 主要失败类型 |
| B2 漏检侧最佳 smoke IoU 中位数 | 0.6468 | 很多样本的位置仍不算差 |
| B2 漏检侧最佳 smoke 置信度中位数 | 0.0429 | 但烟雾类别把握很低 |
| A1/B2 同一主导检测头 smoke 响应中位数 | 0.8978 / 0.0077 | B2 内部类别响应明显下降 |

**IoU** 表示预测框与真实框的重叠程度，范围为 0 到 1，越高表示位置越准确。

这些数据说明：B2 的主要问题不是完全找不到烟雾区域，而是部分目标经过 P4 和后续多尺度传播后，烟雾类别响应被压低。

### 4.3 已经排除或尚未证明的解释

- smoke 的训练正样本数量没有明显减少，不能简单归因于正样本分配失败；
- 共享 neck 和检测头没有出现持续增强的类别梯度冲突；
- P4 局部梯度关系存在波动，但不足以单独证明因果关系；
- P4 `gamma-zero` 能恢复部分内部响应，说明 P4 变换强度参与了问题，但不是唯一原因；
- P03 中 8 种 P4 方向/强度干预均未稳定改善最终检测，排除仅调整 P4 方向性修复 B2 的可能。

**neck** 是融合不同尺度特征的网络部分；**检测头**负责最终输出类别、位置和置信度。

## 六、所有 Pilot 必须遵守的规则

### 6.1 数据与模型

- 数据集使用 RGBT-3M 正式 train/val 划分，不修改验证标签；
- 涉及模型预测时，默认比较 A1 和 B2 的 `last.pt`；
- 必须记录实际 checkpoint，不能只写实验名称。checkpoint 指训练过程中保存的模型权重文件，例如 `last.pt`；
- 同一视频的相邻帧不能随机分到训练和测试两侧，否则结果会虚高。

### 6.2 必须保留的目标分组

| 内部名称 | 含义 |
| --- | --- |
| `a1_hit_b2_miss` | A1 检出、B2 漏检 |
| `a1_miss_b2_hit` | A1 漏检、B2 检出 |
| `both_hit` | A1、B2 都检出 |
| `both_miss` | A1、B2 都漏检 |
| `fire` | 火焰真实目标对照 |
| `person` | 人员真实目标对照 |
| `hard_background` | 外观像烟雾但没有烟雾标签的困难背景 |

目标尺寸统一分为 `<32`、`32-64`、`64-128`、`128-256`、`>=256`。统计时必须同时控制视频来源和目标尺寸。

### 6.3 结果怎样才算可信？

- 同时报告均值、中位数和数据分布，不能只挑一个数字；
- 使用 95% 置信区间表示结果可能波动的范围；
- 必须跨视频验证，不能只在单个视频上有效；
- 必须同时检查 smoke、fire 和 person，不能只看总体 mAP；
- 必须区分“原图能区分类别”和“原图能解释模型漏检”，二者不是一回事。

**AUC** 用于衡量一个指标区分两组样本的能力：0.5 接近随机，0.7 表示具有可用区分能力，1.0 表示完全区分。

### 6.4 Pilot 与 C 系列的关系

满足以下条件，可以进入下一步 Pilot：

1. 区分 smoke 与 fire/person/困难背景的 AUC 不低于 `0.70`，并且跨主要视频方向一致；
2. 区分 B2 新增漏检与稳定检出 smoke 的 AUC 不低于 `0.65`，可信范围不跨 0.5；
3. 冻结主网络后，加入候选信息能稳定提高 smoke 判断能力；
4. 对网络进行对应的临时干预时，烟雾响应出现方向一致的恢复。

进入下一步 Pilot 不等于批准正式 C 系列。正式 C 系列至少还需要满足：

- 能解释为什么该信息应加入网络；
- 跨视频结果稳定；
- 对 B2 漏检或 smoke-vs-background 判断有明确增量；
- 不明显破坏 fire/person；
- 能通过独立消融证明收益来自目标设计，而不是额外参数量。

## 七、P01：三类目标的原图物理画像

**状态：已完成。**  
**完整报告：** `runs/detect/adr004/pilot/P01_physical_profile/report_revised.md`  
**输出目录：** `runs/detect/adr004/pilot/P01_physical_profile/`

### 7.1 P01 做了什么？

P01 直接分析 RGB 和红外原图，没有分析模型。共处理：

- 11220 张 RGB/红外配对图像；
- 30777 个真实目标；
- 21756 个低重叠目标，用于减少烟雾框中混入火焰的影响。

测量内容包括亮度、饱和度、暗通道、梯度、纹理能量、边缘比例、目标/背景对比和 RGB/红外边缘关系。

### 7.2 为什么要控制视频和尺寸？

fire/person 以小目标为主，smoke 中大目标更多。目标尺寸本身会影响边缘和纹理统计。因此 P01 主要在同一视频、相近尺寸内比较，再汇总各组结果。

下面的“方向效应值”范围为 -1 到 1：负数表示 smoke 的该指标更低，正数表示 smoke 更高；绝对值越大，差异越明显。

### 7.3 关键结果

| 比较 | 指标 | 控制视频和尺寸后的 AUC | 方向效应值 | 跨分组方向一致率 |
| --- | --- | ---: | ---: | ---: |
| smoke vs fire | RGB 平均变化 | 0.7184 | -0.4368 | 0.8000 |
| smoke vs fire | RGB 纹理能量 | 0.7702 | -0.5405 | 0.9333 |
| smoke vs fire | 红外平均变化 | **0.9134** | -0.8267 | 0.9333 |
| smoke vs fire | 红外边缘比例 | **0.8760** | -0.7521 | 0.9333 |
| smoke vs fire | 红外目标/背景对比 | **0.8194** | -0.6388 | 0.9333 |
| smoke vs fire | RGB/红外边缘重合度 | 0.7744 | -0.5489 | 0.9333 |
| smoke vs person | RGB 平均变化 | **0.7859** | -0.5719 | 0.8571 |
| smoke vs person | RGB 纹理能量 | **0.8005** | -0.6010 | 0.8571 |
| smoke vs person | RGB 暗通道均值 | 0.7367 | +0.4735 | 0.7143 |

### 7.4 P01 说明了什么？

得到支持：

1. smoke 的 RGB 边缘和纹理弱于 fire/person；
2. smoke 与 fire 的主要差异是红外热结构；
3. smoke 与 person 的主要差异是 RGB 轮廓和纹理；
4. RGB/红外边缘关系可以辅助区分 smoke 与 fire。

没有得到稳定支持：

1. 简单 FFT 高频比或频谱斜率可以统一描述 smoke。FFT 是把图像拆解为不同变化频率的一种计算方法；
2. 暗通道可以同时稳定区分 smoke、fire、person；
3. 单一 RGB/红外全局差值可以作为通用 smoke 指标。

**P01 判定：**通过类别物理画像阶段，可以进入 P02/P04；但它只证明类别之间存在差异，没有证明这些特征能修复 B2。

## 八、P02：原图物理特征能否解释 B2 新增漏检？

**状态：已完成。**  
**完整报告：** `runs/detect/adr004/pilot/P02_b2_smoke_failure_physics/report.md`  
**输出目录：** `runs/detect/adr004/pilot/P02_b2_smoke_failure_physics/`

### 8.1 P02 做了什么？

验证集共有 4086 个 smoke 真实目标：

| 分组 | 数量 | 含义 |
| --- | ---: | --- |
| A1、B2 都检出 | 3564 | 稳定检出 |
| A1、B2 都漏检 | 256 | 两个模型都困难 |
| A1 检出、B2 漏检 | 182 | B2 新增漏检，主分析对象 |
| A1 漏检、B2 检出 | 84 | B2 新增检出 |

每个 B2 新增漏检目标匹配最多 3 个同视频、相近尺寸和相近场景的稳定检出目标，最终得到 182 个病例和 537 个对照。

### 8.2 原图指标能否预测 B2 漏检？

| 原图指标 | B2 新增漏检中位数 | 稳定检出中位数 | AUC | 95% 可信范围 |
| --- | ---: | ---: | ---: | ---: |
| RGB 平均变化 | 0.18288 | 0.17731 | 0.48501 | 0.44911–0.52023 |
| RGB 纹理能量 | 0.05793 | 0.06221 | 0.50744 | 0.47561–0.53800 |
| RGB 边缘比例 | 0.15548 | 0.15219 | 0.48889 | 0.45108–0.52689 |
| 红外平均变化 | 0.12995 | 0.12938 | 0.50287 | 0.46560–0.53973 |
| 红外纹理能量 | 0.02091 | 0.01920 | 0.49292 | 0.45626–0.53114 |
| 红外边缘比例 | 0.04537 | 0.04461 | 0.51328 | 0.47742–0.54843 |
| 红外目标/背景对比 | 0.03633 | 0.04074 | 0.51195 | 0.47321–0.54865 |
| RGB/红外边缘重合度 | 0.03907 | 0.04105 | 0.50183 | 0.46708–0.53550 |

8 个 AUC 全部接近 0.5，远低于预设门槛 0.65，而且所有可信范围都跨过 0.5。因此单个原图指标没有预测能力。

把 8 个指标组合起来并进行跨视频测试后：

- 汇总 AUC：`0.45995`；
- PR-AUC：`0.23696`；
- 随机基线：`0.25313`。

**PR-AUC** 更关注少数的 B2 新增漏检样本。它低于随机基线，说明组合特征也没有稳定预测能力。

### 8.3 网络内部有什么差异？

虽然原图指标不能预测漏检，但网络内部差异明显：

| B2-A1 内部变化 | 新增漏检组中位数 | 稳定检出组中位数 | 区分 AUC |
| --- | ---: | ---: | ---: |
| neck P3 目标区域峰值 | +0.04153 | +0.50242 | 0.74869 |
| 检测头 P3 smoke 响应 | -0.00003 | 0.00000 | 0.72659 |
| 检测头 P2 smoke 响应 | -0.00000 | 0.00000 | 0.70118 |
| neck P4 目标区域峰值 | **-0.10085** | +0.21259 | 0.69568 |
| neck P4 目标区域能量 | **-0.02933** | +0.02364 | 0.67572 |

“B2-A1”表示 B2 数值减去 A1。负数意味着 B2 的响应更弱。

在 182 个新增漏检样本内部，原图结构强度与 fused P4 能量变化存在中等偏弱关系。fused P4 指 RGB 和红外两路 P4 特征融合后的结果。红外边缘、红外梯度、RGB/红外边缘重合度、RGB 梯度的相关程度分别为 `0.3817/0.3678/0.3617/0.3600`。

这表示原图结构会影响 P4 特征，但仍不足以决定最终是否漏检。

### 8.4 临时关闭 P4 变换后怎样？

| 临时干预 | 内部响应恢复数 | 含义 |
| --- | ---: | --- |
| gamma-zero | 31 | 关闭 P4 整体变换强度 |
| cross-zero | 14 | 关闭双向跨模态交互 |
| RGB cross-zero | 7 | 只关闭进入 RGB 的交互 |
| IR cross-zero | 12 | 只关闭进入红外的交互 |

恢复标准是内部最大 smoke 响应从 `<0.25` 达到 `>=0.25`，不等于最终检测结果一定恢复。

gamma-zero 可恢复样本略偏弱 RGB 结构，但 RGB 平均变化和边缘比例 AUC 只有 `0.5911/0.5837`，仍不足以形成可靠规则。

### 8.5 P02 最终判定

1. H3 的广义表述不成立：B2 新增漏检不能由弱边缘、弱红外对比或低跨模态边缘一致性单独解释；
2. 不批准仅依据 P01 原图指标设计的 C 系列结构；
3. 当前更直接的证据指向 P4 后的 neck P3/P4 和检测头响应变化；
4. P04 后续已证明原图物理信息对 smoke-vs-background/fire 有增量，但仍不能声称它直接解释 B2 Recall 损失。

## 九、P03：P4 Parallel Cross A2C2f 方向性干预能否改善最终检测？

### 9.1 结论

P02 已经证明：B2 新增漏检的烟雾在 neck P3/P4 和检测头中的响应明显下降，临时关闭 P4 变换强度能让部分样本的内部响应恢复。P03 进一步追问：

> 这些内部响应变化，能否在完整验证集上转化为最终检测指标的稳定改善？

答案是：**不能。**

对 B2 的 P4 `DualParallelCrossA2C2f` 模块做 8 种推理阶段干预，在 RGBT-3M 完整验证集（3366 张图像、9227 个实例）上逐一验证后，得到：

1. **没有任何干预在 overall mAP50-95 上超过原始 B2。**
2. **部分干预能轻微提高 smoke Recall，但会同时降低 smoke mAP50-95 或破坏其他类别。**
3. **临时关闭 RGB 方向残差（`gamma_rgb=0`）和减半跨模态交互强度（`cross_scale=0.5`）对 smoke Recall 的增益最大，但都不足以形成可靠方案。**
4. **加倍跨模态交互强度（`cross_scale=2.0`）全面恶化。**

因此，P03 不支持"仅通过调整 P4 变换强度或方向就能修复 B2 smoke Recall"的判断。P04 后续验证了物理信息是否能在网络已有特征之外提供增量。

完整报告：`runs/detect/adr004/pilot/P03_p4_intervention/report.md`

### 9.2 干预模式

所有干预都在同一个 B2 checkpoint 上进行：

`runs/detect/train_MF_DMGInit8dP2_FreAttP3_pcrossP4/weights/last.pt`

| 干预 | 参数设置 | 含义 |
|------|----------|------|
| **original** | 不改 | B2 原始对照 |
| **gamma_zero** | `gamma_rgb=0, gamma_ir=0` | 关闭 P4 整体残差变换 |
| **gamma_rgb_zero** | `gamma_rgb=0` | 只关闭 RGB 方向残差 |
| **gamma_ir_zero** | `gamma_ir=0` | 只关闭 IR 方向残差 |
| **cross_zero** | `cross_scale_rgb=0, cross_scale_ir=0` | 关闭双向跨模态交互 |
| **cross_rgb_zero** | `cross_scale_rgb=0` | RGB 不再接收 IR 引导 |
| **cross_ir_zero** | `cross_scale_ir=0` | IR 不再接收 RGB 引导 |
| **cross_scale_0.5** | `cross_scale_rgb=0.5, cross_scale_ir=0.5` | 减半跨模态 delta |
| **cross_scale_2.0** | `cross_scale_rgb=2.0, cross_scale_ir=2.0` | 加倍跨模态 delta |

### 9.5 关键分析

1. **没有任何干预全面提高 smoke。**
   - `gamma_rgb_zero` 使 smoke Recall 提高 0.00367，但 smoke mAP50-95 下降 0.00298，overall mAP50-95 下降 0.00147。
   - `cross_scale_0.5` 使 smoke Recall 提高 0.00364，但整体 mAP50-95 仍下降 0.00035。
   - 两者只是"用定位质量换召回率"，没有真正修复 smoke。

2. **关闭 IR 方向比关闭 RGB 方向更温和。**
   - `gamma_rgb=0`：smoke R 上升，但损伤 mAP50-95 和 overall。
   - `gamma_ir=0`：overall 几乎不变，但 smoke R 反而下降。
   - 说明 IR 方向残差对维持 smoke 召回更重要，RGB 方向残差则会压制部分 smoke 响应。

3. **跨模态交互强度存在上限。**
   - 减半（0.5）影响很小；加倍（2.0）使 overall mAP50-95 下降 0.00386，smoke mAP50-95 下降 0.00584。
   - 当前 `cross_scale=1.0` 已经处于或接近有效上限。

4. **内部响应变化不等于最终检测变化。**
   - P02 中 `gamma-zero` 能让 31/182 个新增漏检样本的内部 smoke 响应恢复。
   - P03 中 `gamma_zero` 在完整验证集上使 smoke Recall 下降 0.00545。
   - 局部恢复被更多原本稳定检出样本的新增漏检抵消。

### 9.6 P03 最终判定

1. P4 模块对 RGB/IR 两个方向的贡献不对称：IR 方向残差对 smoke Recall 更关键。
2. 跨模态交互强度已超过最优区，加倍会同时恶化 smoke、fire、person。
3. **不存在一种简单的 P4 方向性干预能稳定提高 smoke Recall 同时保持 mAP50-95。**
4. P4 变换强度本身不是 smoke Recall 损失的唯一瓶颈。

P03 关闭了一条 shortcut：不要仅通过调整 P4 Parallel Cross 的强度或方向来修复 B2 smoke Recall。

### P03：P4 不同模态方向的临时干预

### P04：物理信息是否提供网络中缺失的信息？

### P05：候选信息应该加入哪个特征层？

**状态：已完成。**

P05 冻结 B2，分别抽取 P2/P3/P4/P5 单层 ROI 特征，再分别追加 IR/RGB/Combined 物理信息，用 ridge logistic 判断器做 leave-one-video-out，判断哪一层最适合注入物理信息。

**结论：**

| 任务 | 最佳层级 | 最佳特征集 | AUC | ΔAUC | 改善视频 |
| --- | --- | --- | ---: | ---: | ---: |
| smoke vs hard_background | **P2** | Combined | 0.93286 | +0.36834 | 8/8 |
| smoke vs fire | **P3** | Combined | 0.93403 | +0.38878 | 8/8 |
| smoke vs person | **P2** | Combined | 0.72861 | +0.17462 | 6/8 |

关键发现：

1. **P2/P3 显著优于 P4/P5。** 三个任务的最佳或次佳结果都在 P2 或 P3。
2. **不同任务偏好不同层：** background → P2，fire → P3，person → P2/P3。
3. **IR-structure 在 P3 对 smoke-vs-fire 最强**，ΔAUC +0.37159。

## 十一、C1 设计方案与结果

### C1.1 方案名称

B2 + Physical Guidance Module（PGM）@P2/P3

### C1.2 设计依据

- P05 显示 smoke-vs-background 最佳在 P2，smoke-vs-fire 最佳在 P3，smoke-vs-person 在 P2/P3 较弱。
- Combined 物理信息始终优于单模态。
- P04b 排除维度/置乱伪影。

### C1.3 模块结构

在 `DualStreamDetectionModel` 的 P2/P3 融合特征后插入轻量 `PhysicalGuidance` 模块：

```
输入 (B, 6, H, W)
  ├── IR  x[:, :3]
  └── RGB x[:, 3:]
       ... backbone ...
       ... DMGFusion@P2, FreDFT@P3 ...
       fused_p2 ──→ PhysicalGuidance(p2) ──→ enhanced_p2
       fused_p3 ──→ PhysicalGuidance(p3) ──→ enhanced_p3
       ... 原 B2 neck/head 不变 ...
```

`PhysicalGuidance` 对每层做：

1. 从原始 RGB/IR 计算 6 张物理图：
   - RGB 梯度幅值、IR 梯度幅值
   - RGB 局部对比、IR 局部对比
   - RGB/IR 边缘一致性、边缘差异性
2. 用小 CNN 编码物理图并下采样到该层分辨率。
3. 与 fused 特征拼接后经 1×1 卷积压缩回原通道数。
4. 通过可学习标量门控 `γ`（初始 0.01）做残差注入：`output = fused + γ · guidance`。

| --- | ---: | ---: |
| B2 | 4,901,106 | 0 |
| C1 | 4,950,260 | +49,154（约 +1.0%） |

### C1.5 训练命令

```bash
python train.py \
```

也就是说，`C1` 的结果更接近“略高于 A1 的 overall、高于 B2 的 smoke Precision，但没有恢复 smoke Recall，且还丢掉了部分 fire/person 收益”。

#### 是否通过 C1 标准？

未通过。

逐条对照 `C1.6`：

1. **smoke Recall 相对 B2 稳定提高**：未满足；
2. **smoke mAP50-95 不明显下降**：基本满足，但没有换来 Recall 恢复；
3. **fire/person mAP50-95 损失 ≤ 0.002**：未满足；
4. **跨视频 smoke Recall 提升方向一致**：未做逐视频复核，但由于总体 Recall 未超过 B2，已无继续判定必要；
5. **参数量/速度损失可接受**：满足。

#### C1 的最终结论

`PhysicalGuidance@P2/P3` 证明了一个更具体的事实：

> 即使 Pilot 证据表明物理信息在冻结特征分析中有增量，把这些物理图以轻量门控残差形式直接注入 P2/P3，也不足以在完整检测训练中稳定修复 B2 的 smoke 问题。

因此，C1 不作为保留方案。它更像一个负结果证据：**smoke 问题不是简单缺少低层物理先验，而是涉及更深层的类别竞争与表示重分配。**

## 十三、C 系列正式实验规则

### 13.1 命名规则

- `C0`：B2 对照，不代表重新训练；
- `C1` 及后续编号：只分配给通过 Pilot 证据筛选的正式方案；
- 未通过的想法保留在“候选与排除记录”，不占编号；
- 每个 C 实验只改变一个主要因素；
- 组合方案必须先完成各组成部分的独立实验。

### 13.2 统一训练设置

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| data | `ultralytics/cfg/datasets/RGBT-3M.yaml` | 数据配置 |
| input_mode | `dual_input` | RGB/红外双输入 |
| imgsz | `[480, 640]` | 输入尺寸 |
| epochs | 200 | 训练轮数 |
| batch | 16 | 每批样本数 |
| optimizer | SGD | 优化器 |
| lr0 | 0.01 | 初始学习率 |
| seed | 0 | 随机种子 |
| deterministic | True | 尽量保证可重复 |
| val_period | 2 | 每 2 个 epoch 验证一次 |
| 主入口 | `train.py` | 统一训练脚本 |

正式比较必须使用相同 checkpoint 类型、验证集和验证参数，并至少报告：

- all/smoke/fire/person 的 Precision、Recall、mAP50、mAP50-95；
- smoke 的不同尺寸结果；
- smoke Recall 峰值、最终值和后期下降量；
- 恢复了多少旧漏检，又新增了多少漏检；
- 参数量、计算量和推理速度；
- fire/person 是否被破坏。

### 13.5 保留和淘汰标准

C 系列首要目标是缩小 B2 相对 A1 的 `0.02223` smoke Recall 缺口，同时保留 fire/person 收益。

优先保留：

1. smoke Recall 稳定提高，mAP50-95 不明显下降；
2. fire/person mAP50-95 损失分别不超过 `0.002`，除非 smoke 收益足够大；
3. smoke 后期 Recall 下降减轻；
4. 逐目标分析确认恢复了困难烟雾，而不是只改变阈值分布；
5. 收益能由对应 Pilot 和独立消融解释。

直接淘汰或降为诊断支线：

- 只提高 Precision，Recall 继续下降；
- 总体 mAP50-95 提高，但 smoke Recall 更差；
- 只在单一视频或尺寸区间有效；
- 无法证明收益来自目标设计；
- 明显破坏 fire/person。
